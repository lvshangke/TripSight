> 回到 [README](../README.md)

## 🌟 满配效果：一份只属于你的、可核对的行程

把高德 key、nanobot 聊天助手、飞猪/RollingGo 只读查询都接上（`python -m tripcore doctor` 会告诉你还缺什么），你会得到这样一套工作方式：

- **真实路线，不是模拟。** 配置高德后，`refine_routes` 把每一段通勤换成高德返回的真实路线：步行/公交/驾车时间、换乘次数、步行距离、票价、线路摘要，地图上画的是真实路线形状。没配 key 时才退回直线估算，并在页面上明确标成“估算”。
- **每个地点都对应真实存在的地方。** 加景点时坐标来自地图搜索结果（网页里不能手填坐标），名字相符且不歧义才会加入；营业时间用 `fill_hours` 向高德核实；到达时间对照营业时间逐站检查。查不到就写“待核实”，不会编一个看起来合理的数字。
- **随时去外面查资料。** 想看别人怎么玩，一句话就能拿到小红书、大众点评、马蜂窝的搜索链接，在你自己的浏览器里用自己的账号看；机票、火车票、酒店参考价通过只读技能查询，不订不付。
- **把别人的攻略变成你的行程。** 把任何一篇攻略/游记贴进来，代码逐条核对原文出处，你挑选哪些加入；加入之后每一个景点都可以**定点修改**——换天、移出、锁定、改停留时长、改顺序——不用推倒重来，改完自动重新检查。
- **最大程度严谨。** 闭馆日、到达时已关门、过了最晚进入、太赶、路上太久、没预约、住宿太远、天气不适合户外、大交通衔接……全部由代码检查，问题直接标在景点下面；所有修改先成为提案、你确认才生效，随时撤销。
- **独一无二，合理可行。** 你的节奏、步行上限、地铁偏好、住宿预算、饮食偏好会被记住并自动套用；住宿按每晚推荐住在哪一带，用餐就近安排——最后得到的是按你的习惯定制、而且排得通的行程，而不是一份通用模板。
- **想加地方、换酒店，随时重新规划。** 行程可以反复规划修改：
  - 新增**你个人想去的地方**（或另一篇攻略里的景点）、**添加或更换住宿**、改住宿分段、改日期、改节奏或步行偏好之后，对助手说“重新规划 / 重新分天”，它会用最新的景点和住宿重排每天的路线；单一住宿时分天会围绕酒店，换成多家酒店（分段住宿）时每天的出发和返回按对应那晚的住宿算。
  - 你已经确认、锁定的安排默认不动，只重排其余部分；真想全部重来，明确说“包括锁定的也重排”。
  - 重排后，网页里的“更新路线”按钮（或让助手 `refine_routes`）会把新安排的每一段补成高德真实路线。
  - 它不会自动重排：加了地方或改了住宿，要你说一声才会重排，改动前后都可以对比；每次重排都是一个版本，不满意可以撤销。
  - 一天装不下的景点会列在“未安排”里并写明原因（超出每日容量等），你可以增加天数、调高节奏，或换掉别的景点。
  - 每天是否装得下，看“游览 + 当天实际路上时间”是否超过节奏上限；游览时长若攻略或你没给，助手会凭常识估一个并告诉你“这是我估的”，你随时可以改。
  - 排完后如果有景点被落下或某天很满，助手可以试算一份**轻松版**（每天只用上限的 80%）和当前版对比，你同意才会应用，可撤销。
- **花多少钱，心里有数。** 按人数估算门票、你选定的餐厅人均和住宿，并**按天显示预算**；机票、火车票、酒店的参考价只读查询，都带来源和日期，查不到就写“待核实”，不编数字；超出你记下的预算或住宿上限会提醒。
- **出发前先看天气。** 日期定下后 `get_weather` 查每天的天气（国内用高德，高德没有的日期或境外用 Open-Meteo，免费、无需 key）；户外景点遇到坏天气会被标出来，让你决定要不要换天。
- **回来之后能复盘。** 旅行结束记下每个景点的实际情况和各类实际花费，`show_review` 把**计划和实际**摆在一起，给出可写进偏好的建议（比如没去的景点多，就建议下次把节奏设为悠闲；备注提到太累，就建议调低步行上限），记不记由你决定，下一次规划会自动套用。
  - 复盘之后还能**写游记草稿**：`draft_travelogue` 只整理你记录过的事实（去了/没去、评分、备注），默认不含酒店和花费；写完 `check_travelogue` 会抓出“提到没去的景点、对不上记录的金额和时间、出现酒店名”。感受和形容无法核实，由你自己读、自己改。
  - 写作模板：`style` 可选**小红书 / 朋友圈 / 通用**，返回段落结构、语气和长度提示；小红书的话题标签只由事实生成（目的地城市 + 你去了的景点，最多 5 个），不凑热门标签。
  - **旅途照片**：`add_photo` 把你自己拍的照片挂在某个景点或某一天，存入时用 Pillow 重新编码，**去掉 EXIF 定位**并缩小（没装 Pillow 就拒绝保存，绝不原样存带定位的文件）；不会去网上找图。分享长图/网页加 `show_photos` 才会把照片放在对应景点下面，默认不带。
- **一键串联全程所有路线。** 行程定稿后：
  - `refine_routes`（网页里的“更新路线”按钮）一次性补全每一天所有路段的真实路线；
  - `create_amap_map` 把每天“酒店 → 景点 → 用餐 → 酒店”的闭环直接生成高德 App 专属地图链接（也可合成一张）；
  - `export_map` / `export_gpx` / `export_text` 生成手机版地图页、轨迹文件和可发微信的文字版。
  - `export_share` 生成**可分享的行程长图（PNG）和单文件网页**：每天一张卡片（日期块、景点数/路程/用时、每站时间和营业时间、交通、天气、地图链接）。**默认不公开酒店和花费**，你要才带；不含航班车次号，不含 key，不嵌地图。长图需要可选依赖 Playwright，没装就只出网页。

  旅途中打开链接就能按顺序走，不必再一段一段地重复查路线。

> 以上“满配”指配齐 key 和各项只读技能之后的效果。

## 🔍 功能详解

### 1. 自动分天：地理 + 容量 + 营业时间

`schedule_days` 把入围景点分到每一天：先按地理位置聚类，再做跨天移动/交换来降低总路程，天内顺序用精确搜索（≤7 个点）或最近邻加 2-opt。**营业时间是排程的一部分**：到达日期已知时，闭馆的日子不会被选中，来不及赶在闭馆前的顺序会被惩罚；全部日子都去不了的景点会被放进“未安排”并说明原因。已锁定的条目永远不动。同样的输入总是得到同样的结果。

### 2. 营业时间与到达时间核查

`check_plan` / `show_trip` 用同一套时间线算出每个景点的预计到达与离开，对照营业时间：当天闭馆、到达时已关门、超过最晚进入、停留越过闭馆、到得太早要等、一天拖到太晚。营业时间的解析很保守：支持“周二至周日 09:00-17:00”“3~10月”“11月15日起周一闭馆”这类写法，遇到看不懂的写法就如实说“无法自动判断”，不猜。网页工作台会在每个景点和每一天下面直接显示这些问题。

### 3. 提案、确认与撤销

助手不能直接改行程。它先用 `propose_change` 生成提案（移动、移出、改状态、锁定、改停留时长），你会看到“改前 → 改后”和一个 4 位确认码，回复确认码才会套用。每次修改都记入版本历史，`undo` 可连续撤销；套用时还会检查版本号，行程被别处改过就拒绝，避免覆盖。

### 4. 真实路线与出行偏好

配置高德后，`refine_routes` 把估算的通勤升级为真实路线：步行/公交/驾车时间、换乘次数、步行距离、票价、线路摘要。偏好会真正影响选择——最多换乘几次、更愿意坐地铁、单段步行上限、是否接受打车；`compare_transport` 可并排比较三种方式，`set_leg_mode` 可单独指定某一段。单段超过约 80 km 会被标为跨城路段并建议改查高铁。境外行程可改用 Google Maps（`set_provider`），没有 key 时用 OpenStreetMap 兜底。

### 5. 住宿区域推荐

`suggest_lodging` 按**每一晚**算推荐：取当晚前一天最后一个、后一天第一个景点的重心，相邻几晚靠得近就合并成一段连住，景点分在不同城市时自动分成几段并提示中途换酒店。像华山这类远郊一日游会被识别出来，酒店仍推荐住主城区。每段给出中心、半径、`search_near`（“某某附近”）和相关景点，助手据此去搜酒店；候选酒店按通勤和价格排序，长途旅行用 `set_stays` 分段住宿。区域只是按景点位置算的建议，酒店价格只用你提供的或工具查到的。

### 6. 用餐

`suggest_food` 在某天某个景点附近搜餐厅（评分、人均、营业时间、距离），你选定后 `choose_food` 才写入；`find_food` 用于“我就想吃这家”——按店名找到后，由代码算出离哪一天哪个景点最近作为建议位置。用餐点不占景点容量。系统会按每天的游览时段判断“还缺午餐/晚餐”，在定稿清单和网页里提醒，网页每天顶部直接有“找午餐”按钮。

### 7. 游记/攻略 → 候选景点

把一篇游记（比如从小红书、公众号复制的正文）整段贴给助手：模型只负责读文字、列清单，**代码负责核对**——每个候选的原话必须逐字出现在原文里且包含地名，线索必须是原文片段，对不上的直接拒收；候选按原文顺序排列并去重。你挑选后，才用地图查坐标，名字相符且不歧义、不与已有景点重合才会加入。游记里的价格、营业时间、“建议上午去”只作为待核实线索，营业时间再用 `fill_hours` 向地图核实。顺路路线（如 citywalk 老菜场→永宁门）可用 `add_route_place` 整条作为一项。
> 目前的输入是你**粘贴的文字**；仓库里没有抓取小红书的代码。

**提交时自动对应真实地点和链接。** 候选一提交，代码就用地图（有高德或 Google key 时）查一遍，每个景点标出 **已匹配**（附地址和地图链接）、**有歧义**（有同名地点，要你确认）、**没找到**，并附上去小红书、大众点评、马蜂窝看这个景点的跳转链接。这只是标注，景点还没加入行程；一次最多预查 30 个。

**别人的分天行程怎样融合进来。** 代码（不是模型）从原文里识别“第N天 / Day N / D2”标记，每个候选记下它在游记里属于第几天。加入之后有两种用法：
- **参考式（默认）**：`compare_with_source` 只读，告诉你游记里同一天的景点在我们的行程里是否还在一起；被拆开时给出原因（某天闭馆、相距太远，或排程为了整体路程更顺）。
- **照搬式**：你明确说“按游记原样排”，`follow_source_days` 才把游记第 N 天的景点放到我们的第 N 天（也可以指定对应关系，比如游记第 1、2 天放我们的第 2、3 天）并锁定，天内顺序仍由排程优化。去不了的（闭馆、营业时间对不上）照放但如实列出，再用我们自己的校验器核查路程、节奏等问题。整个操作是一个版本，可以撤销；已被你锁定的景点不会被动。

**景点的可展开介绍。** 提交时模型要给出游记里讲这个景点的**原文段落**（最多 300 字），代码核对必须逐字出现在原文里，对不上就拒收。加入后工作台里每个景点下面有“▸ 游记里怎么说”，点开是这段原文，并标明“他人说法，未核实”。介绍不由模型自己写，所以每一句都能追溯到出处。
>
> **想先去看看别人怎么玩？** 助手可以用 `search_links` 给你小红书、大众点评、马蜂窝的搜索链接（网页工作台里每个景点下面也有“看攻略”入口，每天缺饭的提示旁有“看点评”，酒店行和未选住宿的天有“看酒店价格”，指向携程、大众点评、小红书；酒店价格和日期、房型有关，链接不带日期，点开后自己选日期，看到合适的价格告诉助手，它会记成“用户提供”）。链接由你自己点开、用自己的账号登录，TripSight 不抓取、不碰你的账号；看到合适的攻略，把正文复制回来即可。链接格式没有用真实账号逐一验证，打不开时请告诉我们。

### 8. 大交通、天气与参考价

`set_connection` 记录到达/离开的航班或火车，代码按“到达时间 + 出站 + 到酒店路程”算出第一天几点能开始玩，按“起飞时间 − 提前量 − 到机场路程”算出最后一天最晚几点出发，首末日容量随之缩小。深夜的接驳段（23:00–05:30）自动改按打车计算。`get_weather` 查已确定日期的天气（高德约 4 天、Open-Meteo 最长约 16 天，每天按当天景点位置查），遇到雨雪高温的户外景点会提醒。机票、火车票、酒店参考价通过技能调用飞猪 flyai 和 RollingGo 命令行**只读查询**，不预订、不支付。

### 9. 带走行程：微信、手机、高德 App、GPX

- **微信 / 聊天里看**：`export_text` 由代码生成适合手机的纯文字行程（每天的出发时间、各站停留和营业时间、交通方式、预约、用餐、天气，每站附地图链接），发出的文字留在聊天记录里，不依赖电脑开着；输出前有外发检查，含 key、本机路径的内容会被拒绝。nanobot 自带 `weixin` 渠道，可以直接在微信里和助手对话（见 [docs/SETUP.md](SETUP.md) 第 7 节）。
- **手机版地图页**：`export_map` 生成按天分色、带时间线的 HTML；`share=True` 生成适合发到聊天里的手机版文件。
- **高德 App 专属地图**：`create_amap_map` 把每天的闭环行程（酒店 → 景点 → 酒店）直接交给高德官方服务，返回在高德 App 里打开的链接，整个过程不经过模型。
- **GPX**：`export_gpx` 导出每天的轨迹，可导入其他地图或运动类 App。
- **出发前复查**：`check_trip_changes` 重新查天气和营业时间，只报有实际影响的变化（新出现的雨雪/高温、气温大幅变化、营业时间变了），只读、不改行程；第一次只建立基线。
- **行程手册**：`export_handbook` 生成可直接打开的手册网页（封面、每天路线图和时间表、每站手账卡）、每天一张 3:4 卡片和发布文案；照片、视频只用你给的原文件，默认不带照片，酒店和花费不出现。小红书只生成发布包，由你自己上传。
- **Obsidian 笔记 / 日历**：`export_notes` 导出一个笔记文件夹（每天一篇、每个景点一篇、`[[双链]]`、轨迹、已挂的照片，可选 vlog 视频）和一个 `.ics` 日历文件，只写本机，不连账号；已有导出不会被覆盖。

### 10. 本机网页工作台

`python -m tripcore web --open`：左侧按天的行程列表，中间地图，右侧聊天助手，三栏之间的分隔条可拖动。

- **查看模式**：按天分页签，景点详情、通勤、用餐、问题提示，点击联动地图。
- **编辑模式**：上下移动或拖到别的天、直接改停留时长、“＋ 加景点”（查询地图后选结果，坐标不能手填）、月历选日期；松手后先显示“改前 → 改后”和新增问题，点确认才生效。
- **多行程**：顶部下拉切换行程，或点“＋ 新建行程…”填表创建（长期偏好自动套用）。
- **聊天**：把消息转给本机的 nanobot，助手改了行程后页面自动刷新并补查路线；顶部显示助手是否已连接。
- **安全**：只监听 127.0.0.1，网址带一次性令牌并校验 Host/Origin，提交带版本号，空闲 2 小时自动退出。

### 11. 长期偏好与旅行复盘

你明确说过的偏好（“我不爱走路”“以后住宿别超过 400”“不吃辣”）会跨行程保存，新行程自动套用节奏、步行、地铁、换乘等偏好；只记你说过的话，不推断。旅行结束后可以记录每个景点的实际情况和各类实际花费，`show_review` 给出计划与实际的对比和可写入偏好的建议，由你决定记不记。

### 12. 定稿前清单

`final_check` 把还没弄清楚的事一次列清：行程检查的所有问题、哪几晚没有住宿、大交通是否已订、天气是否查过或过期、待核实的资料、没匹配到地图的点、仍是估算的交通、哪几天还缺饭。分为必须处理、建议处理、提示三级，只读不改行程。
