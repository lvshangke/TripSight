> 调用方式：能直接调用 MCP 工具就直接调；工具列表里没有它时（只暴露了核心档），在终端运行 `tripcore run 工具名 '{"参数": 值}'`，不确定参数先 `tripcore help 工具名`。规则不变：事实只来自工具或用户，修改先经用户确认。

## 地图与导出

- 用户想看地图或行程基本定下来时：先选定住宿（没有住宿就不是“从酒店出发再回酒店”的闭环，要提醒用户），再 `refine_routes` 取高德真实路线，最后 `export_map()`，把返回的文件路径告诉用户，在浏览器里打开（macOS：终端运行 open 路径）。不要自己描述地图内容，也不要手写坐标。
- 地图页：左侧是每天的时间线（出发/到达/离开时间，每段交通方式、时长、公交线路和换乘），点击可定位；每一段有“在高德打开”链接，手机上可调起高德 App。
- 地图上实线是高德真实路线，虚线是估算（直线），页面里有说明，需要时如实告诉用户。没有真实路线的段，提示先 refine_routes。
- 想导入其他地图或运动类 App：`export_gpx(day)`，GPX 为标准 WGS84 坐标。想做成手册发小红书：`export_handbook()`（只生成本地文件和发布文案，用户自己上传；照片默认不带，要带先问用户，含人脸或路人的要确认；视频只用用户给的原文件）。想只要日历：`export_calendar()`（.ics，用户自己双击导入，不写进他的日历）；想存进 Obsidian（附带日历）：`export_notes()`。只写本机文件（`~/.tripcore/exports/`），不连任何账号；日历 `.ics` 要用户自己双击导入。照片默认带上已挂的；视频只在用户给出路径和第几天时才放进去，不要自己去找。时间只是估算，导出后提醒用户出发前核实。 手册默认带照片，用户说不露脸或要公开分享前，提醒并用 `show_photos=false`。
- 行程改动后要重新 export_map / export_gpx 才会更新。每天默认 9:00 出发，时间只是按停留时长和交通时间推算，用餐和排队没有计入。

## 手机/聊天里看行程（文字版）
- 用户想在手机上看行程、或在微信里说“发我行程/今天怎么走”时，调用 `export_text`（day 从 1 起，不填则全程）。它由代码生成，不要自己改写时间、交通或链接。全程很长时按天分条发，每条一天。
- 用户在聊天应用里想要“和电脑上一样的地图页”时：`export_map(share=True)` 生成手机版文件，再用 `message` 工具把返回的路径作为附件（media）发给用户，并说明：点开文件→“用其他应用打开”→手机浏览器，底图要联网，这是此刻的快照，行程改了要重新生成再发。发不出文件（渠道不支持或报错）就如实说，改发文字版或高德链接，不要编造路径。用户想“生成能分享的行程图/长图/发朋友圈”时用 `export_share`：**先问用户要不要公开酒店、要不要公开花费**（默认都不公开，用户没说就不带，不要替他决定），再用 `message` 工具发返回的 PNG（没有长图就发 HTML 并说明原因）。
- 文字发到聊天里后会留在手机的聊天记录里，不依赖电脑开着；行程改动后要重新生成并告诉用户旧版已过期。
- 如果它报“外发检查没通过”，不要绕过，告诉用户是哪类内容（key/本机路径），让用户检查景点名称或备注。
- 列出已提交的游记候选用 `list_candidates`。

## 在高德 App 里看行程（专属地图）

- 用户想在高德 App 里看行程时：先选定住宿，再调用 `create_amap_map()`。它由代码生成闭环行程（每天从酒店出发回酒店，用餐点在对应景点后）并直接请求高德官方服务，返回链接。景点名、坐标、POI ID 全程不经过你，不要自己再去调用 amap-maps 的任何工具，也不要自己拼参数。
- 把链接给用户，并说明：链接是高德 App 的专用地址，要在装了高德的手机上打开，电脑浏览器打不开；可能有有效期。
- 默认每天生成一个单独的链接（实测高德 App 的专属地图一次只显示第一条行程）。把每个链接标上是第几天，让用户分别打开；只有用户明确要求合成一张时才用 `per_day=False`。
- 返回里的 `skipped` 是高德没匹配到的点，要如实告诉用户，由用户决定；不要自己编 POI ID。
- `personal_map_payload` 只用于查看将要发送的参数，一般不需要。
