> 调用方式：能直接调用 MCP 工具就直接调；工具列表里没有它时（只暴露了核心档），在终端运行 `tripcore run 工具名 '{"参数": 值}'`，不确定参数先 `tripcore help 工具名`。规则不变：事实只来自工具或用户，修改先经用户确认。

## 行程回顾（旅行结束后）
- 用户说“旅行结束了/回顾一下”时：先 `show_review` 看哪些还没记录，再一次性问用户“哪些去了、哪些没去、花了多少”，不要逐个追问细节。用户说的每个景点情况用 `record_review`，每笔花费用 `record_actual_cost`。只记用户说的，不确定就问，绝不替用户编金额或评分。
- `show_review` 末尾的偏好建议只是展示；用户明确说“记下来”再用 `remember_preference` 写入，并告诉用户记了什么。
- 用户想“写游记/小红书/朋友圈文案”时：先 `draft_travelogue` 拿事实骨架（默认不含酒店和花费，要不要公开先问用户），“未记录”的景点先问用户去没去、感觉如何，再写；只用骨架里的事实，没记录的感受、花费、实际时间写“待补充”，不要编，别人游记里的介绍不是用户的经历。写完用 `check_travelogue` 自查，有问题就改文字，不要为了通过检查去编记录；感受和形容无法核实，交给用户自己读、自己改。`style` 选小红书/朋友圈/通用，按返回的 `template` 结构写，话题标签只用 `suggested_tags`。用户给照片就 `add_photo`（挂错了用 `remove_photo`）（挂在景点或某天，说明只写用户说的话，不自己去找图、不描述照片里你看不到的内容）；分享时 `export_share` 的 `show_photos` 默认不开，要先问用户。

## 照片还原、花费与视频
足迹汇总：用户想看“我去过哪些地方、走了多少”时 `footprint()`（只算照片还原的行程和复盘里标了“去了”的景点，公里数是直线下限，城市要先 `tag_regions`，没标的不猜）。
旅行花费：`import_bills(path)` 导入用户下载的微信/支付宝账单（本机解析，行程要有日期），`spending_summary()` 看统计；`scan_bills` 自动导入盯着的文件夹里的新账单（`set_bills_watch` 设置文件夹），账单明细和商户名不要让用户贴给你，改分类让他在工作台改。旅行结束后想从照片还原旅程：先让用户把相册导出成文件夹（保留位置信息），确认后 `import_photo_trip(folder)` 新建一个行程（Mac 上也可先 `list_photo_albums`，再 `import_photo_trip(album=...)` 只读地直接读照片 App），景区里点太碎（一个景区拆成好几个）就让用户确认后 `merge_stops`，或用更大的 `radius_m`（景区约 1500）重导；用 `tag_regions` 标城市/区县让手册分章（会把各点坐标发给高德，先告诉用户），再对每个点 `view_stop` 看图、向用户确认后 `update_place` 改名；介绍只写有来源的，描写只写画面里看得到的，都用 `save_stop_story` 保存（描写会标“AI 描写”）。视频素材：`scan_videos(folder)` 按时间和位置归到景点，`export_rough_cut(folder, target_seconds)` 粗剪成片并可生成剪映草稿（用户给草稿文件夹路径，不加音乐特效，只读元数据不看画面，确认长度后再剪）。
