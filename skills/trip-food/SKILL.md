> 调用方式：能直接调用 MCP 工具就直接调；工具列表里没有它时（只暴露了核心档），在终端运行 `tripcore run 工具名 '{"参数": 值}'`，不确定参数先 `tripcore help 工具名`。规则不变：事实只来自工具或用户，修改先经用户确认。

## 沿途美食

- 用户想吃饭或问“附近有什么吃的”时：调用 `suggest_food(day, after_place_id)`（可加 keyword，如“面食”“清真”），把候选（名称、评分、人均、营业时间、距离）原样展示给用户，由用户挑选。
- `final_check` 或页面里提示“第 N 天还没安排午餐/晚餐”时，主动问用户要不要找；用户说“找第 N 天的午餐/晚餐”就按上面的流程对该天游览中间或最后的景点调用 `suggest_food`，让用户选。这只是提醒，用餐点不占景点容量。
- 评分和人均是高德参考值，不是实时价格，要这样告诉用户；营业时间为空就说“待核实”。
- 用户明确选定后才调用 `choose_food(candidate_id)`；不要替用户挑，也不要自己编餐厅或价格。取消用 `remove_food`。
- 用餐点不占景点容量；`show_trip` 里会显示，并给出已选餐厅的人均参考合计（没乘人数，不计入粗略费用）。
- 有具体日期时，营业时间会按日期和季节条件（如“11月15日起周一闭馆”）自动判断；判断不了就显示“待核实”，不要自己推断。

## 用户自己想吃的店 与 人数

- 创建行程时要问清人数，`new_trip` 传 travelers；中途变化用 `set_travelers`。门票、餐饮的总额按人数估算，住宿按整间/整晚价，人数不会乘到住宿上。
- 用户说出想吃的店名：先 `find_food(店名)`，把高德找到的店（地址、评分、人均）和代码算出的建议位置（第几天、哪个景点之后、距离）展示给用户，让用户确认是不是这家、位置合不合适。确认后 `choose_food(candidate_id)`；用户想换天或换景点，就传 day 和 after_place_id。
- 带 warning 的（离所有景点超过 3 公里）要明确告诉用户要额外花交通时间，由用户决定是否保留。
- 不要自己编店名、地址或价格；高德找不到就请用户提供地址。
